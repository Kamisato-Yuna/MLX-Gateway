# 客户端工作面板

主窗口提供「运行日志」「快速测试」「性能分析」「客户端更新」。切换面板会保留测试草稿和正在执行的任务；侧栏选择模型后，仍需手动启动，API 请求不会自动加载或切换模型。

## 运行日志

- 每 0.75 秒读取最近 64 KB，保留原来的滚动跟随开关和访达入口。
- 错误、警告、成功信息按级别着色；可以搜索并高亮命中文本，或仅显示警告与错误。原始日志中的 ANSI 颜色控制码不直接显示。
- 「清理运行日志」在确认后清空本地 `backend.log` 的历史内容，覆盖所有模型。模型继续运行，后续日志继续追加。日志不可恢复，需要保留时请先通过访达复制。
- 日志属于本机运行数据，可能包含本机路径；分享前请检查和脱敏。

## 性能分析

资源采样可暂停，间隔可选 1、2、5、10、30、60 秒；保留最近 900 次采样。数据来自系统对当前 MLX 主进程的统计：

| 指标 | 定义 |
| --- | --- |
| CPU | 两次采样之间用户与内核 CPU 时间增量；单核满载为 100%，多核可以超过 100% |
| 物理占用 | `ri_phys_footprint`，操作系统归属该进程的物理内存占用 |
| 驻留内存 | `ri_resident_size`，该进程当前驻留内存 |
| 磁盘读写 | `ri_diskio_bytesread` / `ri_diskio_byteswritten` 累计值，随 JSON 报告导出 |

进程停止、不可访问或暂停采样时显示状态；历史曲线与最后采样时间保留。不同 PID、进程启动时间变化后重新计算 CPU，避免模型切换或 PID 重用污染结果。资源统计不包含后代进程；不提供 GPU 利用率，也不把物理占用称为 Metal 专用显存。

请求统计保留本次应用启动最近 500 条，包括模型 ID、起始时间、总耗时、流式首内容延迟（TTFT）、HTTP 状态、token usage 和固定错误码。不会记录提示词、响应正文或认证信息。可按模型筛选，表格展示最近 50 条，导出保留全部记录。

- P50/P95 使用成功请求耗时的 nearest-rank 分位数。样本少时只能作为当前样本描述。
- 非流式无法观测第一个 token，TTFT 显示 `—`。
- 输出 tok/s = 输出 token 数 / 请求总耗时，包含提示词处理，不能当作纯解码速度。
- 失败请求计入失败数，不计成功延迟均值与分位数。重复完成回调只记录一次。
- 「清空统计」清空已完成请求与资源历史，进行中的请求完成后仍会加入。

## 预置性能测试

可选短响应、持续生成、长输入或自定义提示词，设置 1–20 轮与输出上限。请求串行执行，使用当前已启动模型，`stream=false`、`store=false`。默认预热一轮，不纳入本组结果，但预热本身仍是网关请求，会出现在总请求统计。

遇到 HTTP、协议或网络错误后停止本组；取消保留已完成轮次。该面板测试当前配置下的表现，不自动修改模型设置，也不建立固定性能基准。

客户端更新源、分发包与安装行为见 [更新说明](updates.md)。协议支持范围见 [README](../README.md#接口)。
