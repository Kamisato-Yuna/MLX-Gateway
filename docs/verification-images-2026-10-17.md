# 图像服务接入记录

日期：2026-10-17。环境：Apple Silicon，48 GiB 内存，Xcode 27.1，Swift 6，arm64。以下记录区分代码验证和真实模型验证。

## 接入范围

- 新增独立图像服务。侧栏提供手动启动、停止、生成预览和保存 PNG。
- 配置保存在用户运行目录的 `image-service/gateway.json`。公共模型列表和状态不返回本机模型路径。
- 开放 `POST /v1/images/generations`。同步返回 `data[0].b64_json`。不支持编辑、流式生成、URL 输出或 Responses 图像生成工具。
- API 请求不启动、加载或切换模型。未启动时返回 503。没有配置时返回 404。
- 使用本机已有的 `mlx-serve 26.9.6`。未下载或修改模型文件。

## 权重核对

指定的 `qwen-image-2.1-UC-MLX-8bit.safetensors` 是 DiT 权重。已有适配目录还包含 text encoder、processor、scheduler 和 VAE。

原文件和适配副本共 761 个张量。逐张量比较确认：形状、类型及 7,559,831,552 字节数据相同。适配副本只重命名了 9 个张量键。未重新量化，未修改原文件。

## 协议验证

`./script/test.sh` 全部通过：现有 Responses、媒体和音频协议共 207 项检查通过；音频控制器测试通过；新增图像测试通过。图像测试覆盖配置、手动启停、成功 PNG、参数错误、忙碌请求、无效 PNG、下游失败、推理中停止和路径脱敏。fixture 不证明真实模型推理。

## 真实模型限制

在独立测试端口 44329 显式启动相同图像服务代码。下游 44130 的 Metal 进程成功执行，但 `mlx-serve` 拒绝加载模型：预估模型峰值约 20.31 GB，含预留空间要求约 23.8 GB 可用内存，当时约有 7.97 GB。

因此，本轮没有取得真实 PNG，也没有完成模型推理质量验收。未使用 `--skip-mem-preflight`，未关闭用户的其他进程。释放足够内存后，还需手动启动模型并验证出图。

应用重启后，原生界面自动化恢复。已实际确认图像侧栏、模型信息、启动按钮和内存不足提示。通过界面手动启动时，后端再次因可用内存约 6.4 GB 而拒绝加载。未完成真实图像预览或保存对话框验收。
